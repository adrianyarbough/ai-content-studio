# Security Best Practices Report — Floodify Prompt Engineer

## Executive Summary
This audit reviewed the Express server (`server.js`), the Workers/Hono app (`src/index.tsx`), and the vanilla JS frontend (`public/app.js`, `public/index.html`). The system has sensible defaults (CORS allowlist, body size limits, parameterized D1 queries), but there are **high‑impact XSS risks in the frontend** and **missing auth enforcement if `ADMIN_API_KEY` is unset**. CSP is currently permissive because of inline scripts/handlers. These issues should be addressed before public portfolio exposure.

---

## High Severity (Resolved)

### FND-001 — DOM XSS via `innerHTML` in deployment logs
- **Rule ID:** JS-XSS-001
- **Severity:** High
- **Status:** Fixed
- **Location:** `public/app.js` (log rendering)
- **Fix:** Logs now use DOM APIs with `textContent` instead of `innerHTML`.

### FND-002 — DOM XSS via gallery modal content
- **Rule ID:** JS-XSS-001
- **Severity:** High
- **Status:** Fixed
- **Location:** `public/app.js` (gallery modal)
- **Fix:** Modal content is built with DOM nodes and `textContent` for prompt text.

### FND-003 — State‑changing APIs unauthenticated when `ADMIN_API_KEY` is unset
- **Rule ID:** EXPRESS-AUTH-001 / EXPRESS-CSRF-001 (contextual)
- **Severity:** High
- **Status:** Fixed
- **Location:** `server.js`, `src/index.tsx`
- **Fix:** Added `REQUIRE_ADMIN_KEY` guard (defaults to true in production). Returns 503 if missing.

---

## Medium Severity (Open)

### FND-004 — CSP allows `unsafe-inline` due to inline scripts/handlers
- **Rule ID:** JS-CSP-002
- **Severity:** Medium
- **Location:**
  - `server.js:41-55` (CSP header)
  - `public/index.html:6, 26-66` (inline `onclick` and `<script>`)
- **Evidence:**
  - `script-src 'self' 'unsafe-inline' ...`
  - inline `<script>` in HTML and inline `onclick` handler
- **Impact:** CSP is weakened and provides limited protection against XSS.
- **Fix:** Move inline script and handlers into `public/static/app.js` and remove `'unsafe-inline'` from CSP.

---

## Low Severity (Open)

### FND-005 — Error details returned to clients
- **Rule ID:** EXPRESS-ERROR-001
- **Severity:** Low
- **Status:** Fixed
- **Location:** `server.js`, `src/index.tsx`
- **Fix:** Errors are now sanitized unless `EXPOSE_ERRORS=true`.

### FND-006 — CDN assets loaded without SRI
- **Rule ID:** JS-SRI-001
- **Severity:** Low
- **Location:** `public/index.html:8-10, 34`
- **Evidence:**
  - `<link rel="stylesheet" href="https://cdnjs.cloudflare.com/...">`
  - `<script src="https://cdn.tailwindcss.com"></script>`
  - `<script src="https://cdn.jsdelivr.net/.../axios.min.js"></script>`
- **Impact:** CDN compromise could inject malicious code.
- **Fix:** Add SRI hashes or self‑host these assets.

---

## Notes
- Parameterized D1 queries (`prepare().bind(...)`) are used in the main API and help prevent SQL injection.
- CORS is allowlisted and does not reflect arbitrary origins (good). However, this depends on correctly setting `CORS_ORIGIN` for production.

---

## Recommended Next Steps (Minimal-Risk)
1. Move inline script/handlers to JS and remove CSP `unsafe-inline`.
2. Add SRI or self‑host CDN assets.
